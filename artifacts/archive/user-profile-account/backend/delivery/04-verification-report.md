Desvios do plano registrados durante a implementação:

3. `AccountStatus` e `AccountError` ficaram no módulo `auth` do domínio, para não criar a dependência `auth -> account`.
4. O teste de arquitetura ganhou as arestas permitidas entre os módulos novos, sem ciclos.
5. A rota `GET /api/staff/domain-requests` precisou de um caso de uso e de uma consulta novos (`ListDomainRequests`, `recent_requests`), que a spec só citava na API.
6. A prévia de privacidade passou a devolver `public_id`: sem ele, o dono não teria como montar o link da página pública. A lacuna apareceu no fluxo de ponta a ponta.
7. O `build.rs` do `adapters-postgres` recompila o crate quando uma migração muda; sem ele os testes rodavam com o esquema antigo.
8. A comparação de nomes usa uma tabela própria de acentos do português, sem a dependência `unicode-normalization`.
9. `due_for_deletion` não usa `FOR UPDATE SKIP LOCKED`: o `erase` é idempotente e a rotina roda uma vez por vez.
10. Consultas de apoio aos fluxos ficaram no `adapters-postgres`, atrás da feature `test-support` (`FlowProbe`), para o `sqlx` continuar só nesse crate.
