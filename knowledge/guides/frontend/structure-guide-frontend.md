# Structure Guide - Frontend (Angular)

Applies the premise in `commons/project-structure-general.md` to the Angular app.

## Quick rules
- Keep the feature-based folders (`core/`, `shared/`, `features/<feature>/{pages,components,services,models}`); each kind has its own folder and one item per file.
- File name: `<name>.<kind>.ts` in `kebab-case`: `login-request.service.ts`, `login-form.component.ts`, `login-request.model.ts`.
- Kinds and suffixes: `.component`, `.service`, `.model`, `.guard`, `.interceptor`, `.pipe`, `.directive`, `.routes`. [PROPOSED] for the ones beyond `.component`, `.service`, `.model`.
- A component's template and styles keep its base name (`login-form.component.html`, `login-form.component.css`) and stay next to it.
- Unit and component specs live in `__tests__/` inside the folder of the code: `services/__tests__/login-request.service.spec.ts`, `components/__tests__/login-form.component.spec.ts`.
- A spec file name is the source file name with `.spec` before `.ts`; component specs keep `*.component.spec.ts` (the `test:component` split in `testing-guide-unit-frontend.md`).
- Specs import the code under test with `../<name>.<kind>` and never import from another feature.
- Test helpers (fakes, builders) used by one folder live in that folder's `__tests__/`; helpers shared across features go to `shared/testing/`. [PROPOSED]
- `app.ts`, `app.config.ts` and `main.ts` generated by the CLI keep their names; `app.spec.ts` moves to `src/app/__tests__/app.spec.ts`. [PROPOSED]
- Do not create catch-all files (`utils.ts`, `types.ts`, `helpers.ts`); name the file after what it holds.

## Layout example
```text
src/app/
  app.ts
  app.config.ts
  __tests__/
    app.spec.ts
  core/
    api/                      # generated client; do not edit
    interceptors/
      problem.interceptor.ts
      __tests__/
        problem.interceptor.spec.ts
  features/login-request/
    pages/
      login-request.component.ts
      __tests__/
        login-request.component.spec.ts
    components/
      login-form.component.ts
      __tests__/
        login-form.component.spec.ts
    services/
      login-request.service.ts
      __tests__/
        login-request.service.spec.ts
    models/
      login-request.model.ts
```

## Spec example
```ts
// services/__tests__/login-request.service.spec.ts
import { LoginRequestService } from '../login-request.service';

describe('LoginRequestService', () => {
  it('AC-04 [BR-03] exposes the loaded request', async () => {
    // Arrange
    const api = { getLoginRequest: () => of({ id: '1' }) };
    const service = new LoginRequestService(api as unknown as LoginRequestApi);

    // Act
    await service.load('1');

    // Assert
    expect(service.current()?.id).toBe('1');
  });
});
```

## Tooling check
- The test run must pick up nested `__tests__/**/*.spec.ts`; the builder default (`**/*.spec.ts`) already matches them and `tsconfig.app.json` must keep excluding `src/**/*.spec.ts` so specs stay out of the app build. [PROPOSED] Confirm with one failing spec in a `__tests__/` folder (RED) before moving the others.
- A spec outside `__tests__/` next to its source is a verification failure for new code:
```bash
# prints spec files not under a __tests__ folder; empty output = ok (run in frontend/)
find src -name '*.spec.ts' -not -path '*/__tests__/*'
```

## Migrating existing specs
Move one spec per commit (`refactor(frontend): move <name> spec to __tests__`), fix its relative imports, run the unit and component scripts before and after; the list of passing tests must not change.
